Na Jornada vocês viram expectations num pipeline. Hoje: testes que valem para qualquer tabela, com histórico, e constraints.

Mostrar OK não é testar. Um teste precisa de três coisas
1 · Falhar em vermelho

Ninguém precisa abrir uma tabela para perceber. O notebook (ou o job) para.

2 · Deixar registro

Uma linha por teste, a cada rodada. Dá para provar que ontem estava verde e ver quando quebrou.

3 · Conseguir falhar

Teste que nunca falhou pode não estar testando nada. Hoje a gente prova isso.

Antes de confiar no teste, veja ele falhar
WHERE regiao = NULL

Com uma venda sem região colocada de propósito: 0. O teste passa com o dado errado.

WHERE regiao IS NULL

Mesma cópia sabotada: 1. Pegou.

No SQL, NULL quer dizer “não sei”. E “não sei” nunca passa no WHERE
= NULL

regiao = NULL dá “não sei”, nunca verdadeiro. Use IS NULL.

NOT IN

status NOT IN ('criado', …) não pega status nulo. Por isso o T02 tem IS NULL OR.

COUNT(coluna)

COUNT(*) conta linhas. COUNT(regiao) pula os nulos. Os dois juntos mostram quantos faltam.

Tratar valor ausente é tema das duas provas associate. E é a armadilha mais comum em teste de dados.

Constraint barra na entrada, teste confere depois
Constraint (Delta)

Age na escrita. Olha uma linha de cada vez, de uma tabela. Violou? A escrita inteira é recusada.

Teste

Roda depois. Olha qualquer coisa, até duas tabelas juntas. Falhou? Registra e fica vermelho.

Os dois juntos: a constraint segura o que dá para checar linha a linha; o teste cobre o resto.

🏅 Na prova · três jeitos de cuidar da qualidade no Databricks
Constraint

CHECK e NOT NULL numa tabela Delta. Recusa a escrita.

Expectation

Dentro de um pipeline declarativo (Lakeflow). Para cada regra: só registrar, descartar a linha ou parar a atualização.

Teste + alerta

Testes gravados numa tabela, como hoje. Um SQL Alert olha essa tabela e avisa quando passa de um limite.

Perde

🏅 Na prova · Data Analyst Associate

Você quer ser avisada por e-mail quando algum teste da última rodada falhar, sem abrir nada. O que fazer?

A

Um dashboard com os resultados, atualizado à mão toda manhã.

B

Um SQL Alert que conta os FALHOU da última rodada, dispara acima de 0 e manda e-mail.

C

Uma constraint que manda e-mail quando recusa uma linha.

D

Deixar o notebook aberto rodando em loop.

Resposta: B. O alerta roda a consulta no horário, compara com o limite e avisa no destino escolhido. É para isso que a tabela qualidade.resultados_testes existe.

Para levar desta aula
  1. Teste conta linhas ruins, falha em vermelho e deixa registro com histórico.
  2. Veja o teste falhar uma vez. Cuidado com o NULL: = NULL e NOT IN enganam.
  3. Constraint barra na entrada, teste confere depois. E o CREATE OR REPLACE apaga as constraints.
