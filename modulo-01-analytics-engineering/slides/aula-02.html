E para quem trabalha com dados

Muito dado só sai por API

CRM, pagamentos, marketing, sistemas de terceiros: ninguém te dá acesso ao banco deles.

A fonte dita as regras

Limite por chamada, limite por minuto, formato da resposta. O seu código se adapta, não o contrário.

API cai e muda

Fica fora do ar, devolve erro, troca coluna. O pipeline precisa perceber e reagir.

Uma chamada é só uma URL bem montada

GEThttps://datasets-server.huggingface.co/rows?dataset=trilhajornadadatabricks/loja-ficticia-jornada&config=pedidos&split=train&offset=0&length=100

datasetqual dataset (dono/nome)
configqual tabela
splitpartição; aqui sempre train
offseta partir de qual linha (começa em 0)
lengthquantas linhas (máx. 100)

GET = “quero ler”. É o único verbo que a gente usa hoje.

O que volta: JSON, um texto com chaves e valores 
{
  "features": [ {"name": "order_id"}, … ],
  "rows": [
    { "row_idx": 0,
      "row": { "order_id": 1, "valor_liquido": … } },
    … mais 99 linhas
  ],
  "num_rows_total": 1500,
  "num_rows_per_page": 100,
  "partial": false
}
features

A lista de colunas. Vamos comparar com o contrato.

rows

Os dados. row_idx é a posição da linha na fonte.

num_rows_total

Quantas linhas existem. É assim que sabemos quando parar e se veio tudo.

Hora do notebook · Parte 1

Conhecer a API errando de propósito

  • setup/01Criar o ambiente
  • Passo 0Widgets e o contrato das colunas
  • Passo 1A rede deixa? IBGE bloqueado, Hugging Face liberado
  • Passo 2A primeira chamada, olhando a resposta
  • Erro 2Pedir 1.000 linhas de uma vez
  • Erro 3Uma chamada só: 100 de 1.500
O código de resposta diz quem errou
CódigoO que significaQuem errouTentar de novo?
200Deu certoninguém—
400 404 422Pedido errado (ex.: length=1000)nósNão. Corrigir o pedido.
429“Calma, chamadas demais”ninguém: é cotaSim, depois de esperar
500 502 503O servidor falhouelesSim, depois de esperar
timeoutSem resposta, a rede osciloua redeSim, depois de esperar

Regra de bolso: 4xx é com você · 5xx é com eles.

Retry com backoff: tentar de novo sem atropelar
502espera 2 s → 502espera 4 s → 503espera 8 s → 200 ✓
Backoff exponencial

A espera dobra a cada tentativa. Dá tempo para o serviço voltar.

429 · limite de chamadas

Medido em 10/11: ~40 a 55 chamadas seguidas e vem 429. Libera em ~60 s. A carga toda são 76 chamadas.

Tem limite

Depois de 6 tentativas, desiste com mensagem clara. E nunca grava uma resposta de erro como se fosse dado.

Paginação: 1.500 pedidos, 100 por vez
01234567891011121314
Página 0offset=0 · linhas 0–99
Página 1offset=100 · linhas 100–199
Página 14offset=1400 · linhas 1400–1499

Soma 100 no offset até chegar no num_rows_total. No fim: as linhas que vieram batem com o total?

Três decisões na hora de guardar
1 · Resposta crua

Grava o texto exatamente como veio. É a prova do que a fonte mandou, e dá para reprocessar sem chamar a API de novo.

2 · Uma pasta por carga

carga_AAAAMMDD_HHMMSS, em UTC. Nunca sobrescreve: dá para refazer e auditar qualquer dia.

3 · Manifesto no fim

Só escrito se o total bateu. Pasta sem manifesto = carga incompleta, e ninguém lê.

A landing é um arquivo morto: só recebe, nunca altera.

Para levar desta aula
  1. API é a porta combinada para buscar dados de outro sistema. Quem manda nas regras é a fonte.
  2. HTTP 200 não é “veio tudo”. Pagine e compare com o total.
  3. Erro temporário: espera e tenta de novo. Erro nosso: para e avisa. E guarde tudo cru, com recibo.
